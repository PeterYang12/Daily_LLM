# 结论、适用范围与下一步

## 已经得到的结论

### 1. 本机具备真实agent任务的运行和评分基础

固定30B模型、三种harness、每题sandbox、独立判题和结果记录能够连起来。Uni-Agent在其中实际提供agent实现/适配器、工具、Gateway、任务配置与SWE评分组件。

正式外围driver是实验代码；本次没有验证Uni-Agent完整RL训练runner。因此可称为“Uni-Agent推理组件与sandbox集成验证”，不能称为“agentic RL训练闭环已完成”。

### 2. Harness选择会影响同一模型的任务表现与开销

同一有效28题上，ReAct通过17题，Claude11题，Mini12题；ReAct还没有修改既有测试的案例。与此同时，ReAct保留的生成token与任务时间更多。

这为本机下一步研究提供了起点：先以ReAct作为透明、易观察的基线，再比较黑盒CLI在预算、提示与工具策略上的取舍。该建议来自本样本，不推导所有任务上ReAct都更强。

### 3. Sandbox需要按执行位置和控制面分清

模型服务、CPU编排与任务执行是不同容器。Docker客户端在CPU容器，专用dockerd创建任务；ReAct与Claude/Mini的主循环位置也不同。远端E2B可以承接工具操作，但还需要为SWE模板与远端黑盒CLI设计额外集成。

### 4. 先优化单卡，再按并发扩副本有实测支持

在当前短上下文微基准中，eager TP4没有优于TP1；AITER+图执行的单卡改善明显；双副本主要在较高并发下体现收益。结果说明容量规划应看单卡效率、并发、排队与资源消耗，不能只按显卡张数估算吞吐。

### 5. 轨迹捕获和实际训练仍是两件事

本次主实验token/mask有效，三种agent还单独验证了完整logprob记录。训练器输入、loss mask/reward处理、参数更新、权重同步、checkpoint恢复和模型能力提升均未验收。

## 不应从这些结果推导的结论

| 不支持的结论 | 原因 |
|---|---|
| Qwen30B在完整SWE-bench Verified达到60.7% | 只评了分层有效28题，非全量500题 |
| 后训练提升了4.41倍或提升了解题率 | 未做后训练；4.41倍是推理吞吐 |
| 测过Anthropic Claude模型 | 跑的是Claude Code CLI，后端是Qwen |
| E2B已支持本次完整SWE流程 | 远端仅验证了demo与独立代码任务 |
| sandbox实现了强多租户安全认证 | 本次是功能与若干隔离/资源控制验证 |
| 八副本可以线性扩展 | 仅测了两个优化副本 |
| 日志中CLI说成功就代表问题解决 | 有正常结束但独立测试失败的案例 |

## 推荐后续路线（尚未执行）

| 阶段 | 工作 | 完成证据 |
|---|---|---|
| 小规模训练准备 | 固定兼容的ROCm训练依赖，明确算法、训练数据、reward和预算 | 可重复的配置与数据清单 |
| 单步RL验收 | rollout → sandbox工具 → verifier → reward/token mask → loss → optimizer | 梯度/loss有效，参数前后确有变化 |
| 训练运行时验收 | 权重同步、暂停恢复、完整checkpoint | 新策略被rollout使用，重启恢复状态一致 |
| 受控效果比较 | 固定base/final与同一agent/预算，评测集不参与训练 | 逐题差异、重复性、成本与效果报告 |
| 扩大评测 | 增加任务覆盖并处理环境可用性，考虑完整500题 | 完整分母、环境失败与能力失败分列 |
| 平台化 | sandbox模板、网络策略、租约、资源/日志监控 | 可持续运行与可追查的故障边界 |

训练集可考虑SWE-reBench或R2E-Gym等来源，但需先确认数据授权、任务镜像与训练/评测分离。具体方法和参数应在真正启动训练前冻结。本次28题的gold信息不能拿来训练后又在同一题集上宣称泛化收益。

## 面向汇报的准确表述

“我们已经在现有AMD八卡节点上搭起可复现的30B agent运行与独立评分链路，比较了三种harness，验证了本地和远端sandbox路径，并测得明确的ROCm推理优化收益。当前结果用于确定工程基线与后续训练验收方案，后训练效果还需要单独实验。”
